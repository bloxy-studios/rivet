# Getting Started (Contributors)

Honest scope note: Rivet is pre-alpha. What exists today is the foundation — toolchain,
governance, docs, and `@rivet/types`. The apps are placeholders until Phase 1 lands.
Everything documented here works *today*; capabilities that don't exist yet live in the
[phase plan](../plan/phase-plan.md), not here.

## Prerequisites

- [Bun](https://bun.sh) ≥ 1.4.0 — `curl -fsSL https://bun.sh/install | bash`
- Git. (Docker will become a prerequisite when Phase 1 introduces Postgres/ClickHouse
  via compose.)

## Setup

```sh
git clone https://github.com/bloxy-studios/rivet.git
cd rivet
bun install
bun run check   # lint + typecheck + tests — must pass on a clean clone
```

## Commands

| Command | What it does |
| --- | --- |
| `bun run check` | The CI gate: Biome lint → typecheck → Vitest |
| `bun run lint` | Biome check (read-only) |
| `bun run format` | Biome format, writes changes |
| `bun run typecheck` | `tsc --noEmit` in every workspace via Turborepo |
| `bun run test` / `bun run test:watch` | Vitest, root config (`packages/*/src/**/*.test.ts`) |
| `bun run dev` | All apps in dev mode |
| `bunx turbo run dev --filter=web` | One app (`web` or `docs`) |
| `bun run build` | Production builds via Turborepo |

## Repository orientation

- `packages/types` — `@rivet/types`: domain primitives (severities, issue states,
  evidence levels, agent capabilities, the agent run state machine) with invariant
  tests. Read `src/agent-state.ts` first; it encodes the approval gate.
- `packages/typescript-config` — shared tsconfig presets (`@repo/*` = starter tooling).
- `packages/ui` — placeholder components; becomes `@rivet/ui` in Phase 1 (PR-4).
- `apps/web`, `apps/docs` — placeholder Next.js apps; `apps/web` becomes the product
  shell in Phase 1. Their `AGENTS.md`/`CLAUDE.md` files are generated by Next.js —
  don't hand-edit.
- `docs/` — architecture, ADRs, plan, design language. ADRs are binding.

## Conventions that will save you review cycles

- Branch: `type/scope-description` (e.g. `feat/db-control-plane`). Conventional
  Commits, with DCO sign-off: `git commit -s`.
- Internal packages are source-only (`exports` → `./src/index.ts`); don't add build
  steps.
- Pure packages stay framework-free; logic ships with tests.
- New dependency? Check the license allowlist in [../licensing.md](../licensing.md)
  and justify it in the PR.
- UI work follows [../design/design-language.md](../design/design-language.md).

## Working on the database

Tests need **no database and no Docker** — they run on PGlite (in-process Postgres).
For running migrations/seed against a real server locally:

```sh
docker compose -f infrastructure/compose/dev.yml up -d
export DATABASE_URL=postgres://rivet:rivet@localhost:5432/rivet
bun run db:migrate && bun run db:seed
```

Schema changes: edit `packages/database/src/schema/`, run `bun run db:generate`,
review and commit the generated SQL. Details: `packages/database/README.md`.

## Troubleshooting

- **`bun install` resolution errors** — check your Bun version (`bun --version` ≥
  1.4.0); older Bun cannot read this lockfile format.
- **Typecheck differences vs your editor** — the workspace pins TypeScript per package;
  ensure your editor uses the workspace TypeScript version.
- **Biome and your editor disagree** — install the Biome editor extension and disable
  Prettier/ESLint plugins for this workspace; `bun run format` is the source of truth.
